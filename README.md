Theogony 

Theogony არის ბერძნული მითოლოგიის ღმერთების, გმირებისა და ნახევრადღვთაებრივი არსებების არქივი Angular-ზე. თითოეულ პერსონაჟს სამი თვისება აქვს ძალა, გმირობა და სიბრძნე. მომხმარებელს შეუძლია პერსონაჟების ფილტრაცია მათი უნარების მიხედვით, ასევე საკუთარი პანთეონის შექმნა და პატარა მოთხრობების წაკითხვა. 

პროექტის ლოკალურად გასაშვებად საჭიროა ბრძანებები: 
 
```bash 
npm install 
npm start 

გაშვების შემდეგ აპლიკაცია ხელმისაწვდომი იქნება მისამართზე: http://localhost:4200. 

 

პროექტი შედგება რამდენიმე გვერდისგან : 

Home: მისასალმებელი გვერდი სათაურით, ციტატით და ბმულებით კატალოგსა და პანთეონზე. 

The Gods : გამოაქვს მითოლოგიური პერსონაჟების სია კატეგორიის ფილტრითა და ძალის, გმირობისა და სიბრძნის მინიმალური ვარსკვლავების ფილტრებით. 

Პერსონაჟი: ერთი პერსონაჟის სრული გვერდი თვისებებით, აღწერით, ძალებით და პანთეონში დამატების ღილაკით. 

Pantheon: აერთიანებს შერჩეულ პერსონაჟებს, მართავს მათ რაოდენობას და ითვლის ჯამურ მაჩვენებლებს, ასევე აქვს „Dispatch army“ ღილაკი. 

Blog: სტატიებისა და ქრონიკების სიას ნახვების რაოდენობით. 

Contact: ვალიდირებული reactive ფორმა, შეცდომების შეტყობინებებითა და შეტყობინების გაგზავნის სტატუსით 

404 : გვერდი, რომელიც ნებისმიერ უცნობ მისამართზე გამოჩნდება და მთავარ გვერდზე გადაგიყვანს ან კატალოგში დაგაბრუნებს. 

 


არის სამი ძირითადი საქაღალდე: 

core/ — შეიცავს აპლიკაციის ძირითად ინფრასტრუქტურასა, layout კომპონენტებს Header და Footer, რადგან ისინი მთელ აპლიკაციაზე ვრცელდება.  

shared/ — შეიცავს იმას, რასაც რამდენიმე გვერდი იყენებს, კონკრეტულად,  მრავალჯერ გამოყენებად მოდელებს (models), სერვისებს (services) და დამხმარე ვალიდატორებს, რადგან თავიდან ავიცილოთ კოდის დუბლირება და მონაცემთა ტიპები ერთ ადგილას იყოს აღწერილი.  

features/ — მოიცავს ცალკეულ ფუნქციურ გვერდებსა და მოდულებს (home, catalog, product-detail, cart, blog, contact, not-found), ასე თითოეული გვერდის , ლოგიკა და სტილები იზოლირებული და მარტივად მართვადი ხდება. 

 



კალათის მდგომარეობას მართავს CartService (@Injectable({ providedIn: 'root' })), სადაც შენახულია items = signal<CartItem[]> და გამოითვლება totalCount როგორც computed მნიშვნელობა. სერვისის კონსტრუქტორში გამოყენებულია effect, რომელიც items სიგნალის ყოველ ცვლილებაზე ავტომატურად ინახავს მონაცემებს localStorage-ში (theogony_cart), ხოლო აპლიკაციის გაშვებისას აღადგენს მათ. ამის წყალობით გვერდის განახლებისას (F5) კალათის შემადგენლობა და Header-ში არსებული რაოდენობა უცვლელი რჩება. 

 



მონაცემები 

კატალოგი / პერსონაჟები (/data/products.json): იტვირთება ProductService-ის მიერ Angular-ის HttpClient-ით (public/data/products.json) და გამოიყენება კატალოგისა და პერსონაჟის დეტალური გვერდისთვის.  

ბლოგი (https://dummyjson.com/posts): ქრონიკების სია და ცალკეული სტატიები მიიღება PostService-ის საშუალებით HttpClient-ის GET მოთხოვნებით.  

კონტაქტის ფორმა (JSONPlaceholder POST) : ფორმის გაგზავნისას მონაცემები იგზავნება POST მოთხოვნით სერვისის გავლით, რაც საშუალებას გვაძლევს დავამუშაოთ დატვირთვის, წარმატებისა და შეცდომის მდგომარეობები.

წარდგენისთვის 

LO1 Angular: გავხსნი აპლიკაციას http://localhost:4200-ზე და ვაჩვენებ ნავიგაციას Header-ით, აქტიურ ბმულებს (routerLinkActive), დინამიკურ როუტებს (/products/:id, /blog/:id), ტაბის title-ის ცვლილებას და 404 გვერდს.  

LO2 375px: DevTools-ში (Ctrl+Shift+M) გადავრთავ iPhone SE (375px) რეჟიმზე და გავივლი მთავარ, კატალოგის, პანთეონის, ბლოგისა და კონტაქტის გვერდებს ჰორიზონტალური სქროლისა და დარღვეული განლაგების გარეშე.  

LO3 მოქმედება ცვლის ეკრანს: კატალოგში გავფილტრავ ჩანაწერებს, დავამატებ ფიგურას კალათაში, შევცვლი რაოდენობას (+/-/წაშლა), დავაკვირდები computed ჯამებს და განვაახლებ გვერდს (F5), რომ localStorage-იდან აღდგენა ვაჩვენო.  

LO4 მონაცემები სერვერიდან: Network ჩანართში ვაჩვენებ products.json-დან და DummyJSON-დან წამოღებულ მონაცემებს, Offline რეჟიმით შეცდომისა და „თავიდან ცდის“ მუშაობას, ასევე კონტაქტის ფორმის POST მოთხოვნასა და გაგზავნის სტატუსებს.
